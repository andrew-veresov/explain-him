# New-question loop

When the authored page and repository do not provide enough grounded evidence for an answer, the personal agent must not hide the gap.

## Procedure

1. Show the supported part of the answer.
2. Explicitly state what is missing and why.
3. Check existing Issues.
4. Prepare one concrete question for the Originator.
5. Remove irrelevant personal context, secrets, and private material.
6. Draft the repository Issue in English and show it to the user.
7. Create the Issue only after explicit user confirmation.
8. After the Originator responds, move the durable clarification into a resolution, knowledge, or the authored page.

## Why the status is `hypothesis`

GitHub Issues technically provide a free feedback loop. It has not yet been demonstrated that they are sufficient as the only UX for a mass-market end user, so the sufficiency of this channel remains a `hypothesis`.
