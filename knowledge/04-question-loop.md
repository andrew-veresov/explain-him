# Контур новых вопросов

Когда authored page и repository не дают достаточно подтверждённого ответа, персональный агент не должен скрывать пробел.

## Процедура

1. Показать подтверждённую часть ответа.
2. Явно обозначить, чего не хватает и почему.
3. Проверить существующие Issues.
4. Подготовить один конкретный вопрос Оригинатору.
5. Удалить нерелевантный персональный контекст, secrets и закрытые материалы.
6. Показать draft пользователю.
7. Создать Issue только после явного подтверждения.
8. После ответа Оригинатора перенести устойчивое уточнение в resolution, knowledge или authored page.

## Почему статус — hypothesis

GitHub Issues технически обеспечивают бесплатный feedback loop. Пока не доказано, что они достаточны как единственный UX для массового конечного пользователя, поэтому достаточность этого канала остаётся `hypothesis`.
