# Presentation Capability boundary

Accepted resolution:

1. Explain Him defines a Presentation Capability contract rather than owning a universal visualization engine.
2. The personal agent owns question understanding, repository grounding, and meaning formation.
3. A Presentation Capability receives an already-grounded typed Presentation Artifact and does not become a knowledge source.
4. The Originator controls canonical meaning and trusted embedded execution; the Consumer controls personal representation and may use consumer-local capabilities outside the trusted surface.
5. Presentation Artifacts never carry executable HTML or JavaScript for direct DOM injection.
6. External capabilities run agent-side unless an embedded implementation is explicitly trusted and bundled.
7. Archify is a reference `originator-approved` / `personal-agent` capability, not an Explain Him dependency.
8. Browser-local workspace v2 stores generalized presentations and migrates v1 blocks to safe-text artifacts.
